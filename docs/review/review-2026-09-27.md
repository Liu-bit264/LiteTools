## P2 — 备份文件名按秒取时间戳，同秒二次写入会覆盖上一份备份

`generator.py` 与 `ico/generator.py` 都用 `time.strftime("%Y%m%d-%H%M%S")` 生成 `.bak-<秒>` 名。同一秒内对同一目标连续两次写入（脚本化批处理、快速重跑很常见），第二次 `shutil.copy2` 会以“当前已被第一次覆盖的新内容”覆盖同名备份，导致原始文件的备份丢失，备份失去回滚意义。

建议：时间戳加毫秒/计数后缀，或在目标已存在同名备份时追加序号；至少检测 `backup_path` 已存在时换名。

证据：[generator.py](/E:/hw-tools/projects/Library/Software/LiteTools/uvprojx/generator.py:471)、[ico/generator.py](/E:/hw-tools/projects/Library/Software/LiteTools/ico/generator.py:186)

## P2 — chipfill 对芯片清单的字段类型不做校验，畸形 JSON 抛未捕获异常

`load_chip` 只检查顶层必需键是否存在，随后 `_compose_cpu` 直接 `int(v, 16)` 解析 `flash_base`/`flash_size`/`app.base` 等，`derived` 又假设 `memory`/`partitions.app` 为 dict 且含特定子键。若清单中这些值缺失、非字符串或非十六进制，会抛 `KeyError`/`TypeError`/`ValueError`，逃逸出 `ChipFillError` 的处理，CLI 以栈回溯退出而非友好错误。

建议：`load_chip` 校验关键子字段的存在与类型，`_compose_cpu` 对 `int(v,16)` 包裹并抛 `ChipFillError`，与既有错误风格一致。

证据：[chipfill.py](/E:/hw-tools/projects/Library/Software/LiteTools/uvprojx/chipfill.py:54)、[chipfill.py](/E:/hw-tools/projects/Library/Software/LiteTools/uvprojx/chipfill.py:73)

## P2 — generator 更新模式对 group/file 结构类型假设过强

`validate_spec` 只校验 `groups[].name` 与 `files[].path` 非空，但 `_build_groups_element` 遍历时若某个 `file` 不是 dict（例如误写成字符串），`file.get(...)` 会抛 `AttributeError`；`validate_spec` 里 `group.get("files") or []` 对 `files` 为非列表（如对象）也不拦截，后续迭代行为未定义。正常 parser 输出不会触发，但手写 spec 易踩。

建议：`validate_spec` 增加 `isinstance(file, dict)`、`isinstance(files, list)` 校验，把畸形结构收敛为 `UvprojxGenerateError`。

证据：[generator.py](/E:/hw-tools/projects/Library/Software/LiteTools/uvprojx/generator.py:74)、[generator.py](/E:/hw-tools/projects/Library/Software/LiteTools/uvprojx/generator.py:95)

## P3 — ICO 解析器对 BMP/PNG 条目仅做浅校验，可能把损坏条目判为合法格式

`parse_ico_bytes` 判定格式时，只要 `blob[:8]==PNG_SIGNATURE` 即标记 PNG，或 `len(blob) >= 40` 即标记 BMP(DIB)，未进一步校验 `bi_size/bi_planes/bi_compression` 合理性或 PNG 的 IHDR CRC。因此“前 8 字节像 PNG 但其余损坏”或“凑够 40 字节的随机数据”会被识别为对应格式且不计入 `errors`（PNG 缺 IHDR 时仅在 `png.error` 里标注，不影响退出码）。

作为结构校验器这属于“宽松识别”，非安全问题；若用于校验产物完整性建议收紧：PNG 校验 IHDR 存在性并纳入 errors，BMP 校验 `bi_size in {40,...}` 与 `bi_planes==1`。

证据：[ico/parser.py](/E:/hw-tools/projects/Library/Software/LiteTools/ico/parser.py:109)、[ico/parser.py](/E:/hw-tools/projects/Library/Software/LiteTools/ico/parser.py:36)

## P3 — 写入非原子：自校验通过后直接 `write_bytes`/`write_tree` 覆盖目标

generator 与 ICO 生成器都先备份、再直接写目标文件。若写入中途失败（磁盘满、进程被杀），目标会处于半写状态。已有备份可回滚，故列 P3。建议：写临时文件后 `os.replace` 原子替换，进一步降低损坏窗口。

证据：[generator.py](/E:/hw-tools/projects/Library/Software/LiteTools/uvprojx/generator.py:471)、[ico/generator.py](/E:/hw-tools/projects/Library/Software/LiteTools/ico/generator.py:183)
